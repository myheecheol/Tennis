# 코트 렌더러 명세 (v2 — 3D)

> 구현: `web/template.html` · 카메라 값: `data/cameras.json` · 같은 기하의 파이썬판: `tools/court3d.py`
> 구현이 먼저 있고 문서가 따라갑니다.

## v1 → v2 에서 바뀐 것

| | v1 | v2 | 이유 |
|---|---|---|---|
| 코트 | 평면 탑뷰 | **3D 원근** (중계 시점) | 공이 길게 오는지 짧게 오는지 안 보였다 |
| 공 | 고정된 곡선 화살표 | **실제 포물선** + 그림자 + 바운드 링 + 깊이 태그 | 같은 이유 |
| 시점 | 하나 | **중계 / 내 시점** 전환 | "가끔은 주인공 시점으로" |
| 선수 | 평면 원 | 머리 + 몸 + 그림자 (핀) | 3D에서 서 있는 자리가 보이게 |
| 해설 | 2~4문장 | **한 문장** (56자) | 장황했다 |

## 0. 색 — 밝은 잔디 코트 (v3)

중심 색은 **PANTONE 15-0343 Greenery** `#88B04B` (2017 올해의 컬러). 한 가지 밝은 테마로 고정한다 — 다크 모드 기기에서도 밝게 보인다.

| 이름 | 값 | 쓰임 |
|---|---|---|
| Greenery | `#88B04B` | 코트 바깥 잔디 · 주 버튼 · 히어로 |
| 잔디 줄무늬 | `#5A9A3B` / `#66A646` | 코트 안, 깎은 잔디 12줄 |
| 형광 | `#E4FF3D` | 나 · 내 공 · 정답 존 |
| 남색 | `#26357F` | 상대 |
| 하늘 · 방풍막 | `#8FCBEA`→`#E6F5FC` · `#2E5A34` | 내 시점 배경 |
| 글자 | `#16240D` · 강조 `#4A7A1C` (흰 바탕 5.1:1) | |

잔디 위 대비 — 남색 상대 3.2:1 · 흰 파트너 3.4:1 · 형광 나 3.1:1(코트) / 2.2:1(바깥 잔디).
나는 바깥 잔디에서 대비가 낮아 **흰 테두리 + 진한 외곽선**으로 분리한다.
옛 빨강 상대는 잔디와 밝기가 거의 같아(적록색맹에겐 사실상 같은 색) 남색으로 바꿨다.

## 1. 기하

- 정규 좌표 → 월드(미터): `X = (x−0.5)·10.97`, `Y = (1−y)·23.77`, `Z` 높이
- 카메라: 눈 위치 + 바라보는 점 → 핀홀 투영. **근평면(0.3m) 자르기**로 카메라 뒤를 잘라낸다
- 네트는 실제 높이 — 가운데 0.914m, 기둥 1.07m, 기둥은 복식라인 밖 0.914m

## 2. 두 시점

| | 중계 | 내 시점 |
|---|---|---|
| 카메라 | 우리 뒤, 앙각 54°, 거리 64m 망원 | 내 등 뒤 4.2m, 높이 3.4m |
| 맞춤 | 코트+여백 상자를 화면에 자동 맞춤. 위 84 는 시점 버튼과 결과 배지 자리 | 고정 초점 (0.74·화면 높이) |
| 결과 장면 | 고정 | **카메라가 내 등 뒤를 따라간다** — 내가 뛰면 화면이 같이 움직인다 |
| 먼 코트 | 가까운 쪽의 약 80% 크기 | 훨씬 작다 |
| 기본으로 쓰는 카드 | 대부분 | 네트 근처에서 앞을 보는 5장 (C1-03·09·21·22·24) |

**내 시점은 검증기가 허락한 카드만 기본값이 됩니다.** 세 보기 존이 모두 33×33px 이상 보여야 합니다.
베이스라인에서 보는 내 시점은 상대 코트 끝이 325px² 로 너무 작아 탈락했습니다(C1-12).

## 3. 공 궤적

`from → bounce → to` 를 2차 포물선으로 잇는다. 휨 크기는 `arc` 가 정하고, 네트를 넘는 구간은 네트 위 1m 를 지나도록 자동으로 키운다.

| 요소 | 그리는 법 | 읽히는 정보 |
|---|---|---|
| 리본 | 폭이 꼬리 2px → 머리 6px, 거리에 따라 0.55~1.6배 | 방향, 가까움 |
| 입체 화살촉 | 밝은 면 + 어두운 면 두 삼각형 | 끝 방향 |
| 바닥 그림자 | 점선 | **실제 코스** — 리본과 벌어질수록 높은 공 |
| 정점 높이선 | 최고점에서 바닥까지 세로 점선 (1.5m 초과 시) | 얼마나 뜨는지 |
| 바운드 링 | 반지름 0.46m 바닥 원 | 떨어지는 자리 |
| 깊이 태그 | `짧게`<6.4m · `중간`<9.5m · `깊게` (네트에서 거리) + `로브`/`높게`/`낮게` | **길게인지 짧게인지** |

색: 상황 속 공 흰색 · 내 공 형광 노랑 · 상대가 칠 공 남색(흰 테두리).

## 4. 선수

| | 중계 | 내 시점 |
|---|---|---|
| 나 | 형광 머리 + 발밑 빛 | **바닥 링 + `나` 표시** (몸을 그리면 시야 한가운데를 막았다) |
| 파트너 | 흰 둥근 머리 | 같음 |
| 상대 | 남색 네모 머리 | 같음 |

머리 반지름 10~21px, 몸 두께는 머리의 0.62배 이하. 먼 선수부터 그린다.

## 5. 화면 상태

| 상태 | 보이는 것 |
|---|---|
| 풀기 전 — 멈춤 | 도입 공이 날아와 결정하는 순간에 멈춘다. 공에 흰 고리가 맥박치고 `⏸ 지금, 어떻게 할까?` · 보기 존 3곳(점선 + A/B/C) |
| 결과 재생 중 | 고른 존 흰 테두리 · 사람이 뛰고 공이 이어서 난다. 보기 버튼은 잠기고 색은 아직 없다 |
| 결과 | 배지 `✓ 성공` · `△ 아쉬움` · `✕ 실패` + 한 줄(`caption`). 고른 존이 결과 색(초록·노랑·빨강), 틀렸으면 정답 존 노란 점선. 그다음에 해설이 열린다 |
| 정답 장면 보기 | 같은 판에서 정답 보기의 결과를 재생 — 배지 `정답이면 ✓ 성공` |

**검증판 게임은 카드 한 장을 코트 한 화면으로 연출한다** — 제목(어둡게) → 도입 공 → 상황 글(가운데) → 질문 한 줄(위) ·
단서와 보기(코트 아래 줄) → 결과 → 해설(아래에서 올라옴). 무대 API: `mode:'pose'`(도입 직전 자세), `freezeSay:false`(멈춤 배지 없이),
`onFreeze`. 단계표는 `design/08-phase1.md` §1.

공 색은 친 편을 말한다 — **노랑 = 우리, 남색 = 상대, 흰색 = 도입 공**(결과 장면에서는 옅게 남는다).
`winner` 는 바운드 자리에 점선 고리, `call` 은 빨간 판정 글자(`풋폴트` 는 서버 발밑, 나머지는 공이 끝난 곳)를 맨 위에 그린다.

**A/B/C 글자**는 화면에 실제로 보이는 존 영역 안에서 선수에게서 가장 먼 점에 놓는다.
(월드 좌표 모서리에 두었더니 내 시점에서 화면 밖으로 나갔다.)

## 6. 움직임 — 시간표

카드 데이터(`setup.ball`, 보기의 `stand` · `moves` · `play`)에서 **시간표**를 만든다 — 누가 언제 어디로, 공이 언제 어디로.
순서는 `reference/court-coordinates.md` 5.1 과 같고, 검증기 `check_play` 도 같은 순서로 따라간다. 검증기를 통과한 장면은 재생해도 말이 된다.

| 언제 | 무엇이 | 시간 |
|---|---|---|
| 카드를 열 때 | 도입 공이 날고, 끝에서 **멈춘다** | 0.15s 뒤 출발 |
| 보기를 고르면 | 0단계: 내가(또는 `moves` 의 사람들이) 동시에 뛴다 → 공이 차례로 난다 → 받는 사람이 공을 향해 뛴다 | 사람 약 5m/s · 공은 구질별 속도(서브 24m/s … 로브 9m/s), 한 구간 0.4~1.7s |
| `▶ 다시` | 풀기 전: 도입만. 푼 뒤: 도입 → 결과 | |

- 공이 나는 동안에는 지나온 궤적만 그린다(화살촉 없음). 다 날면 화살촉과 깊이 태그가 붙는다
- 재생 중 코트를 누르면 끝 장면으로 건너뛴다. 도입 중에 존을 누르면 도입을 끝내고 바로 결과로
- `prefers-reduced-motion` 이면 움직임 없이 끝 장면만 — 멈춘 화면, 배지, 해설은 그대로
- 끝 장면만 봐도 다 읽힌다: 모든 궤적이 남고, 내가 떠난 자리에 흐린 나 + 바닥 화살표(중계 시점)

## 7. 조작

- 존을 눌러도, 아래 보기를 눌러도 답이 된다 (같은 처리). 움직이는 층은 누름을 통과시킨다 — 선수 핀 위를 눌러도 그 밑의 존이 눌린다
- 한 번 고르면 확정 — 코트에서는 되돌릴 수 없다. `다시 풀기` 로 처음부터
- 틀렸으면 `정답 장면 보기 ▶` ↔ `내 선택 다시 보기` 로 두 장면을 번갈아 본다
- `다음 수 →` 가 `next.id` 카드로 간다 (카드가 랠리로 이어진다)
- ← → 키로 카드 이동, 진행 막대로 바로 가기. 진행은 브라우저에 저장된다

## 8. 깨지기 쉬운 곳

| 증상 | 막는 장치 |
|---|---|
| 서브 위치·방향이 틀린다 (실제로 두 번 났다) | 검증기 — 라인 뒤, 대각선, 서비스 박스 |
| 가까운 존이 카메라 뒤로 넘어가 좌표가 폭주한다 | 근평면 자르기 + 화면 사각형 자르기 |
| 공 경로가 한 점뿐(서브 준비)이면 터진다 | `hold` 는 궤적 없이 공만 그린다 |
| 존이 너무 작아 못 누른다 | 검증기 — 두 시점 모두 넓이 계산 |
| 결과 장면이 채점과 거꾸로다 (실수인데 포인트를 딴다) | 검증기 `check_play` — 마지막 공으로 판정해 채점과 맞춘다 |
| 내 시점에서 뒤로 물러나면 내가 화면 밖으로 나간다 | 결과 장면에서는 카메라가 나를 따라간다 |
| 배지가 먼 선수 머리를 가린다 | 중계 카메라 위 여백 84 |
