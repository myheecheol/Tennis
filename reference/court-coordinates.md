# 코트 좌표계 규격

> AI가 뱉는 위치가 **그대로 화면에 찍히는 좌표**여야 게임이 됩니다.
> 이 규격을 프롬프트에 넣으면 상황 카드가 곧바로 렌더링 가능한 데이터가 됩니다.

---

## 1. 정규 좌표

```
x : 0.0 (왼쪽 복식 사이드라인) → 1.0 (오른쪽 복식 사이드라인)
y : 0.0 (상대 베이스라인)      → 1.0 (우리 베이스라인)   네트 = 0.500
```

| 라인 | y | | 라인 | x |
|---|---|---|---|---|
| 상대 베이스라인 | 0.000 | | 왼쪽 단식 사이드라인 | 0.111 |
| 상대 서비스라인 | 0.223 | | 센터 서비스라인 | 0.500 |
| **네트** | **0.500** | | 오른쪽 단식 사이드라인 | 0.889 |
| 우리 서비스라인 | 0.777 | | | |
| 우리 베이스라인 | 1.000 | | | |

코트 밖도 쓸 수 있습니다 — `y < 0` 은 상대 베이스라인 뒤, `x < 0` 은 왼쪽 사이드라인 밖.

**월드 좌표(미터, 3D 렌더러)** — `X = (x − 0.5) × 10.97`, `Y = (1 − y) × 23.77`(우리 베이스라인 0), `Z` = 높이.

## 2. 존 코드 — `[코트]-[가로][세로]`

- 코트: `A` 우리 / `E` 상대
- 가로: `L` 왼쪽 / `C` 가운데 / `R` 오른쪽 (각 1/3, **항상 우리 베이스라인에서 네트를 볼 때 기준** — 상대 코트도 같은 방향)
- 세로: `N` 네트존 / `M` 미드존 / `B` 베이스존 / `X` 베이스라인 뒤

| 코드 | 우리 코트 y | 상대 코트 y | 쓰임 |
|---|---|---|---|
| `N` | 0.500 ~ 0.640 | 0.360 ~ 0.500 | 발리 자리, 넷맨 발밑 |
| `M` | 0.640 ~ 0.860 | 0.140 ~ 0.360 | 서비스 박스 부근 |
| `B` | 0.860 ~ 1.000 | 0.000 ~ 0.140 | 깊은 공이 떨어지는 곳 |
| `X` | 1.000 ~ 1.098 | −0.098 ~ 0.000 | **선수가 서는 곳** (서버, 뒤로 빠진 리시버) |

> ⚠️ **`X` 존은 공의 목표가 될 수 없습니다.** 베이스라인 뒤에 떨어지면 아웃입니다.
> (초기 규격에서 이곳을 "로브 착지점"이라고 잘못 정의했고, 카드 두 장이 아웃 지역을 보기로 썼습니다.)

| 존 | 별명 |
|---|---|
| `E-LN` / `E-RN` | 상대 넷맨 **발밑** |
| `E-LB` / `E-RB` | **크로스 딥** / 직선 딥 |
| `E-CM` | 두 상대 사이 |
| `A-RX` | 듀스 코트 **서브 자리** (베이스라인 뒤) |
| `A-CN` | 포치 나가는 자리 |

## 3. 공 — 길게인지 짧게인지 화면이 보여준다

```json
"ball": {
  "kind": "와이드 서브",            // 사람이 읽는 이름
  "arc": "serve",                  // 궤적 종류 — 높이를 정한다
  "from": [0.72, 1.02],            // 친 곳 (반드시 치는 선수 위치)
  "bounce": [0.17, 0.27],          // 바운드 — 길게/짧게를 정한다 (선택)
  "to": [0.10, 0.06],              // 받는 곳 (선택)
  "toZ": 1.3                       // 받는 높이 m (선택 — 가슴 높이 발리 등)
}
```

| `arc` | 치는 높이 | 궤적 | 쓰는 곳 |
|---|---|---|---|
| `hold` | — | 공이 손에 있다 | 서브 준비 |
| `serve` / `serve2` | 2.6m | 내리꽂힘 / 한 번 떴다 내려옴 | 퍼스트 / 세컨 서브 |
| `flat` | 0.9m | 낮게 | 발밑 공 |
| `normal` | 0.9m | 보통 | 일반 스트로크 |
| `high` | 0.9m | 높게 | 띄운 공 |
| `lob` | 0.9m | 아주 높게 | 로브 |
| `volley` | 1.0m | 짧고 낮게 | 네트 앞 발리 |
| `smash` | 2.8m | 직선 내리꽂기 | 스매시 |

- 궤적은 **실제 포물선**입니다. 네트를 넘는 구간이면 네트 위 1m 를 반드시 지나도록 자동 보정합니다
- 바운드 지점의 네트에서 거리로 **깊이 태그**가 붙습니다 — `짧게`(6.4m 미만, 서비스 박스 안) · `중간`(9.5m 미만) · `깊게`
- 서브는 태그 대신 `서브`

## 4. 화면에 그리는 것

| 대상 | 모양 |
|---|---|
| **나** | 형광 노랑 머리 + 흰 테두리 + 발밑이 빛난다 + `나` |
| 파트너 | 흰 둥근 머리 `짝` |
| 상대 | 남색 **네모** 머리 `1` `2` — 색 없이도 모양으로 구분. 잔디 위의 빨강은 적록색맹에게 거의 안 보여 남색을 쓴다 |
| 공이 나는 길 | 흰 **리본** — 꼬리는 가늘고 머리로 갈수록 굵다 + 입체 화살촉 |
| 바닥 그림자 | 리본 아래 점선 — 실제 코스. 리본과 멀수록 높게 뜬 공 |
| 정점 높이선 | 가장 높은 곳에서 바닥까지 세로 점선 (1.5m 넘을 때) |
| 바운드 | 바닥 링 + 깊이 태그 |
| 정답 연출 | 노란 바닥 화살표(내 이동) / 노란 리본(내 공) / 남색 리본(상대 공) / 노란 시선선 |

**시점은 중계 하나** (`data/cameras.json` 에서 정의 — 웹과 검증기가 같은 값을 쓴다)

우리 베이스라인 뒤 높은 곳에서 망원으로 본다. 코트 전체와 네 사람이 항상 들어온다.
카드에 `view` 를 적지 않습니다 — 적으면 검증기가 거부합니다 (내 시점은 v8 에서 뺐다, PRD #20).

## 5. 카드 JSON 스키마

```jsonc
{
  "id": "C1-03", "chapter": "C1", "title": "포치, 언제 나갈까요",  // 20자
  "difficulty": 2, "prereq": ["C1-02"], "myRole": "넷맨", "phase": "서브+1",
  "setup": {
    "me":      { "zone": "A-LN", "xy": [0.30, 0.59] },
    "partner": { "zone": "A-RX", "xy": [0.72, 1.02] },            // 서버는 라인 뒤
    "opp1":    { "zone": "E-LB", "xy": [0.08, 0.04] },
    "opp2":    { "zone": "E-RM", "xy": [0.74, 0.30] },
    "ball":    { "kind": "와이드 서브", "arc": "serve", "from": [0.72, 1.02], "bounce": [0.17, 0.27], "to": [0.10, 0.06] }
  },
  "scene": "파트너의 와이드 서브가 리시버를 바깥으로 끌어냈어요.",     // 38자 — 해요체
  "cue": "리시버의 백스윙이 늦어요.",                                 // 26자 — 눈에 보이는 것만
  "question": { "type": "move", "text": "나는 어떻게 움직일까요?" },   // 14자
  "answer": { "zone": "A-CN", "short": "가운데로 두 걸음", "principle": "P-04",
              "why": "밀린 리시버는 크로스로 칠 수밖에 없어요. 그 길목이 가운데예요.",   // short 14 · why 56
              "stand": [0.50, 0.57],                                          // 결과 장면 — 5.1
              "caption": "가로채서 포인트!",                                    // 12자
              "play": [ { "by": "opp1", "arc": "normal", "to": "me" },
                        { "by": "me", "arc": "volley", "bounce": "E-CM", "winner": true } ] },
  "distractors": [
    { "zone": "A-LN", "severity": "차선", "short": "제자리에서 기다리기", "why": "…",
      "caption": "편한 크로스가 이어져요",
      "play": [ { "by": "opp1", "arc": "normal", "bounce": [0.78, 0.90], "to": "partner" } ] },
    { "zone": "A-LM", "severity": "실수", "short": "물러서며 직선 막기", "why": "…",
      "stand": [0.18, 0.72], "caption": "가운데가 뚫렸어요",
      "play": [ { "by": "opp1", "arc": "normal", "bounce": "A-CM", "winner": true } ] }
  ],
  "coachLine": "넷맨은 직선이 아니라 가운데를 먹어요.",               // 24자
  "next": { "id": "C1-15", "text": "포치 뒤엔 자리가 바뀌어요" },        // 18자
  "tags": ["포치", "넷맨"]
}
```

`readNext` 카드는 정답 연출을 적어야 합니다 — `"reveal": {"type": "oppShot", "by": "opp2", "arc": "smash"}` / `{"type": "look", "by": "opp2"}` / `{"type": "move"}`

### 5.1 결과 장면 — 고르면 공과 사람이 그대로 움직인다

도입 공(`setup.ball`)이 날아와 **결정하는 순간에 멈춥니다.** 보기를 고르면 그 보기의 결과 장면이 이어서 재생되고, 끝나면 `✓ 성공` · `△ 아쉬움` · `✕ 실패` 와 `caption` 이 뜹니다. 보기 3개(정답·차선·실수)마다 적습니다.

| 필드 | 뜻 |
|---|---|
| `caption` | 결과 한 줄, **12자** |
| `stand` | 내가 서는 점 `[x, y]` — 고른 존 안. 없으면 존 가운데 (이미 그 존 안이면 제자리) |
| `moves` | 여럿이 움직일 때 `{"me": [x, y], "partner": [x, y]}` — `stand` 대신. `{}` 면 아무도 안 움직인다 |
| `play[]` | 이어지는 공 1~4개. 아래 |

`play` 의 공 하나:

| 필드 | 뜻 |
|---|---|
| `by` | 치는 사람 `me` · `partner` · `opp1` · `opp2`, 또는 `none` (친 사람 없이 흘러가는 공) |
| `arc` | `serve` · `serve2` · `flat` · `normal` · `high` · `lob` · `volley` · `smash` |
| `from` | 출발점 — 보통 생략. 생략하면 공이 공중에 있으면 그 자리, 바닥이면 치는 사람 자리 |
| `bounce` | 바운드 — `[x, y]` 또는 존 코드 (그 존 가운데) |
| `to` | 공이 끝나는 곳 — `[x, y]`, 존 코드, 또는 선수 이름 (그 사람에게 간다) |
| `toZ` | `to` 에서의 높이(m) |
| `reach` | `to` 가 좌표일 때 그리로 뛰어가 받는 사람 — 생략하면 다음 공을 치는 사람 |
| `winner` | `true` — 아무도 못 받는다. 친 팀이 딴다 (`by: none` 이면 공이 떨어진 쪽이 잃는다) |
| `call` | `풋폴트` · `폴트` · `아웃` · `네트` — 친 팀이 잃는다 |

**재생 순서** (엔진과 검증기가 같은 순서로 따라간다):

1. **0단계** — 내가 먼저 움직인다. `moves` → 그대로, 아니면 `stand` → 존 가운데. `move` · `both` 문제와 움직임을 보여 주는 `readNext` 에만 적용. `look` 연출이면 시선 줄이 그어진다
2. 첫 공을 치는 사람이 출발점으로 간다. 도입 공이 바닥에 떨어져 있었다면 바운드한 공이 그 사람 쪽으로 튀어 오른다
3. 공이 차례로 난다. `to` 가 좌표면 받는 사람이 공을 향해 뛴다. 다음 공은 앞 공이 끝난 높이에서 시작한다

**결과 판정** — 마지막 공으로 정한다.

| 채점 | 장면이 끝나는 모습 |
|---|---|
| 정답 | 포인트를 딴다, 또는 랠리가 이어지고 마지막에 친 게 우리 편 |
| 차선 | 랠리가 이어진다 (`winner` 도 `call` 도 없다) |
| 실수 | 포인트를 잃는다 |

## 6. 검증 규칙 — `tools/validate_cards.py` 가 매번 검사

| 규칙 | 이 규칙이 생긴 이유 |
|---|---|
| **서브는 베이스라인 뒤**에서 넣는다 | 서브 장면 11장이 전부 코트 안에서 넣고 있었다 |
| 서브는 **대각선 서비스 박스** 안에 떨어진다 | 서버와 착지점이 같은 쪽인 카드가 있었다 |
| 공을 보내는 보기에 **`X` 존(아웃)** 금지 | "로브" 보기가 아웃 지역을 가리키고 있었다 |
| 공은 상대 코트에 바운드하고, 친 곳엔 치는 선수가 있다 | |
| 좌표는 선언한 존 안 / 마커끼리 0.12 이상 / 정답·오답 존 중복 금지 | |
| 오답은 차선 1 + 실수 1 | |
| 모든 존이 중계 화면에서 **33×33px 이상** 보인다 | 손가락으로 누를 수 있어야 한다 |
| 글자 수 한도 / 설명 없는 전문 용어 금지 | 해설이 장황했고, 용어를 안 풀어 썼다 |
| 문장은 **해요체** — 반말·해라체 어미(`-다` `-까?` `-라`) 금지 | "말만 존댓말로" (사용자 요청) |
| 보기마다 **결과 장면**이 있고, 장면이 끝나는 모습이 **채점과 맞는다** (5.1) | 실수를 골랐는데 포인트를 따는 장면이면 배운 게 거꾸로 된다 |
| 결과 장면의 공도 자기 코트에 바운드하지 않고, 코트 안에 떨어진다 (`아웃` 만 밖) | |
| 결과 장면의 서브도 라인 뒤에서, 대각선 박스로 (`풋폴트` · `폴트` 만 예외) | |
| 공을 보내는 문제는 첫 공을 내가 쳐서 **고른 존에** 떨어뜨린다 | 고른 곳과 공이 간 곳이 다르면 결과를 믿을 수 없다 |
| 한 번에 뛰는 거리 9m 이하 | 더 멀면 사람이 순간이동하는 것처럼 보인다 |
