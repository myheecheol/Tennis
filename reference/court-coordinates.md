# 코트 좌표계 규격 (Court Coordinate Spec)

> 게임을 만들려면 "왼쪽 앞쪽" 같은 말로는 부족합니다.
> AI가 뱉는 위치가 **그대로 화면에 찍히는 좌표**여야 합니다.
> 이 규격을 프롬프트에 넣으면 상황 카드가 곧바로 렌더링 가능한 데이터가 됩니다.

---

## 1. 정규화 좌표 (렌더러가 쓰는 값)

복식 코트 실측: **가로 10.97m × 세로 23.77m** (네트 기준 좌우 대칭)

```
x : 0.0 (왼쪽 복식 사이드라인) → 1.0 (오른쪽 복식 사이드라인)
y : 0.0 (상대 베이스라인)      → 1.0 (우리 베이스라인)
    네트 = y 0.500
```

주요 라인의 y값 (그대로 SVG에 쓰면 됨):

| 라인 | y | 비고 |
|---|---|---|
| 상대 베이스라인 | 0.000 | |
| 상대 서비스라인 | 0.223 | 네트에서 6.40m |
| **네트** | **0.500** | |
| 우리 서비스라인 | 0.777 | |
| 우리 베이스라인 | 1.000 | |

x값:

| 라인 | x |
|---|---|
| 왼쪽 복식 사이드라인 | 0.000 |
| 왼쪽 단식 사이드라인 | 0.111 |
| 센터 서비스라인 | 0.500 |
| 오른쪽 단식 사이드라인 | 0.889 |
| 오른쪽 복식 사이드라인 | 1.000 |

y축을 0.0~1.0 밖으로 쓸 수 있습니다 (`y = -0.08` = 상대 베이스라인 뒤 = 로브 착지점).

## 2. 존 코드 (사람이 읽고, 문제로 출제하는 단위)

정규 좌표는 렌더링용, **존 코드는 정답 판정용**입니다.
탭으로 찍는 게임이니 정답은 "점"이 아니라 "영역"이어야 합니다.

### 구조: `[코트]-[가로][세로]`

- 코트: `A` = 우리(Ally) 코트 / `E` = 상대(Enemy) 코트
- 가로: `L` 왼쪽 / `C` 가운데 / `R` 오른쪽 (각각 1/3)
- 세로: `N` 네트존 / `M` 미드존 / `B` 베이스존 / `X` 베이스라인 뒤(로브존)

### 세로 구간 정의

| 코드 | 이름 | 우리 코트 y | 상대 코트 y |
|---|---|---|---|
| `N` | 네트존 | 0.500 ~ 0.640 | 0.360 ~ 0.500 |
| `M` | 미드존 | 0.640 ~ 0.860 | 0.140 ~ 0.360 |
| `B` | 베이스존 | 0.860 ~ 1.000 | 0.000 ~ 0.140 |
| `X` | 로브존 | 1.000 ~ 1.100 | -0.100 ~ 0.000 |

### 전체 24존

```
        상대 코트 (E)
  E-LX   E-CX   E-RX      ← 로브 착지 / 깊은 아웃
  E-LB   E-CB   E-RB      ← 상대 베이스라인 부근
  E-LM   E-CM   E-RM      ← 상대 서비스박스
  E-LN   E-CN   E-RN      ← 상대 넷맨 발밑 존
================ 네트 ================
  A-LN   A-CN   A-RN
  A-LM   A-CM   A-RM
  A-LB   A-CB   A-RB
  A-LX   A-CX   A-RX
```

> ⚠️ 좌/우는 **항상 "내가 우리 베이스라인에서 네트를 바라볼 때" 기준**입니다.
> 상대 코트의 `E-L`도 내 시점의 왼쪽입니다. 카메라를 절대 뒤집지 않습니다.

### 자주 쓰는 존의 별명 (문제 지문에 쓰는 말)

| 존 | 별명 |
|---|---|
| `E-CN` | 상대 두 사람 사이, 네트 앞 |
| `E-LN` / `E-RN` | 상대 넷맨 **발밑** |
| `E-LB` / `E-RB` | 크로스 **딥** (대각선 깊게) |
| `E-CB` | 가운데 **딥** |
| `E-LX` / `E-RX` | **로브** 착지점 |
| `A-CN` | 포치 나가는 자리 |

## 3. 마커 규격 (누가 어떤 색인가)

**요구사항: "나"는 반드시 다른 색.** 색맹 대응을 위해 **색 + 모양 + 글자** 3중으로 구분합니다.

| 대상 | 코드 | 색 | 모양 | 글자 |
|---|---|---|---|---|
| **나** | `me` | 옵틱 옐로 `#E4FF3D` | 채운 원 + 흰 링 | `나` |
| 파트너 | `partner` | 흰색 `#F2F6F8` | 채운 원 | `짝` |
| 상대 1 | `opp1` | 벽돌빨강 `#D9553C` | 채운 사각형 | `1` |
| 상대 2 | `opp2` | 벽돌빨강 `#D9553C` | 채운 사각형 | `2` |
| 공 | `ball` | 흰색 + 어두운 테두리 | 작은 원 | — |

경로 표기:

| 종류 | 코드 | 선 | 색 |
|---|---|---|---|
| 공이 지나간 길 | `ballPath` | 실선 + 화살촉 | 흰색 |
| 공이 갈 길 (문제) | `ballPathGhost` | 점선 + `?` | 흰색 40% |
| 내 이동 | `myMove` | 굵은 점선 + 화살촉 | 옵틱 옐로 |
| 파트너 이동 | `partnerMove` | 가는 점선 | 흰색 60% |
| 정답 타겟 존 | `targetZone` | 반투명 채움 + 테두리 | 옵틱 옐로 20% |
| 위험 구역 | `dangerZone` | 반투명 채움 (빗금) | 벽돌빨강 18% |

코트 배경:

| 요소 | 색 |
|---|---|
| 코트 안 (인플레이) | `#2F6FA8` |
| 코트 밖 (런오프) | `#1C4C77` |
| 라인 | `#FFFFFF` (90%) |
| 네트 | `#0E1B26` + 흰 테이프 |

## 4. 카드 JSON 스키마 (이대로 뽑으면 바로 개발 가능)

```jsonc
{
  "id": "C1-03",                    // 챕터-순번
  "chapter": "서브 게임",
  "title": "넷맨일 때, 언제 가로채러 나갈까",
  "difficulty": 2,                  // 1~5
  "prereq": ["C1-02"],              // 선행 카드 id
  "myRole": "넷맨",                 // 서버 | 넷맨 | 리시버 | 리시버 파트너 | 랠리
  "phase": "서브+1",                // 서브 | 서브+1 | 리턴 | 랠리 | 마무리

  "setup": {
    "me":      { "zone": "A-RN", "xy": [0.72, 0.60] },
    "partner": { "zone": "A-LB", "xy": [0.24, 0.99] },
    "opp1":    { "zone": "E-LB", "xy": [0.20, 0.04] },   // 리시버
    "opp2":    { "zone": "E-RM", "xy": [0.74, 0.30] },   // 상대 넷맨
    "ball":    { "path": [[0.24,0.99],[0.34,0.18]], "kind": "슬라이스 서브", "height": "낮음" }
  },

  "cue": "리시버가 백핸드 쪽으로 끌려나갔고 라켓 준비가 늦다.",   // 읽어야 할 단서
  "question": { "type": "move", "text": "지금 나는 어떻게 움직일까?" },
                                     // type: move | target | both | readNext
  "answer": {
    "zone": "A-CN",
    "short": "네트를 따라 가운데로 두 걸음, 가로채기",
    "why": "리시버가 밀린 상태라 직선을 칠 여유가 없다. 리턴은 크로스로 온다. 그 길목이 A-CN이다.",
    "principle": "P-04"
  },

  "distractors": [
    { "zone": "A-RN", "severity": "차선",
      "why": "제자리 대기는 안전하지만, 넷맨이 안 움직이면 상대는 편하게 크로스만 반복한다." },
    { "zone": "A-RM", "severity": "실수",
      "why": "직선을 막으려고 사이드로 벌리면 가운데가 통째로 비어 오히려 쉽게 뚫린다 (P-05)." }
  ],

  "coachLine": "넷맨은 직선을 지키는 사람이 아니라, 가운데를 먹는 사람이다.",
  "nextBeat": "포치에 성공하면 파트너가 반대편으로 스위치한다 → C1-04",
  "tags": ["포치", "넷맨", "서브게임"]
}
```

**필수 검증 규칙** (프롬프트에 넣으면 AI가 스스로 지킴)
1. `answer.zone`과 모든 `distractors[].zone`은 **서로 달라야 한다**
2. `distractors`는 **정확히 2개**: `"차선"` 1개 + `"실수"` 1개
   → 3지선다에서 "완전 헛소리 보기"는 학습 가치가 0
3. `answer.principle`은 P-01~P-05 중 하나 (도메인 팩 참조)
4. `question.type`이 `"target"`이면 정답 zone은 반드시 `E-`로 시작
5. `xy`는 존 코드의 범위 안에 있어야 한다
6. `cue`에는 **관찰 가능한 단서만** — "상대가 약하다" 같은 추상어 금지
