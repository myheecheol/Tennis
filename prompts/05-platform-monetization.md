# STEP 5 — 플랫폼·기술·수익화 프롬프트

**목적**: "웹이냐 앱이냐"를 **근거 있게** 결론 내리고, 로드맵과 비용을 확정합니다.
**입력**: STEP 0 + `reference/platform-recommendation.md` + STEP 4 게임 설계
**출력**: 플랫폼 결정 / 기술 스택 / 수익 모델 / 로드맵 / 비용 / 리스크

> 💡 `reference/platform-recommendation.md`에 이미 결론과 근거가 들어 있습니다.
> 이 프롬프트는 그 결론을 **반박하게 만들어서** 검증하는 용도입니다.
> 동의만 하는 AI에게서는 배울 게 없습니다.

당신은 1인~3인 규모 앱 스튜디오를 여러 번 운영해 본 프로덕트 리드입니다.
소규모 팀이 어디서 시간을 낭비하는지 압니다.

위 "플랫폼·수익화 판단" 문서를 **의뢰인의 초안**으로 보고 검토하세요.
동의하는 부분은 동의하되, **틀렸다고 보는 부분은 분명히 반박**하세요.

## 1. 플랫폼 결정 재검토

초안은 "웹으로 검증 → Flutter로 앱 출시"입니다. 아래 4가지 대안과 비교하세요.

| 대안 | 설명 |
|---|---|
| A | 초안대로: 웹 프로토타입 → Flutter 앱 |
| B | 처음부터 Flutter (웹 빌드도 Flutter로) |
| C | 처음부터 Expo(React Native) — 웹·iOS·안드로이드 한 번에 |
| D | 앱 없이 웹만. PWA + 웹 결제로 끝까지 간다 |

각 대안을 **①검증 속도 ②그래픽 품질 ③수익화 ④1인 개발 부담 ⑤6개월 뒤 후회 가능성**
5축으로 평가한 표를 만들고, **하나를 고르고 이유를 3문장으로** 쓰세요.
초안(A)과 결론이 다르면, 어디가 틀렸는지 명시하세요.

## 2. 기술 스택
선택한 대안에 맞춰 확정하세요. 각 항목에 "왜 이걸 골랐나" 한 줄씩.
- 프레임워크 / 코트 렌더링 방식(캔버스·SVG·네이티브 드로잉)
- 카드 데이터 저장 (앱 번들 동봉 vs 서버 — **콘텐츠를 자주 고칠 것**을 고려)
- 백엔드가 필요한가. 필요하다면 최소 범위는
- 분석 도구 / 결제 / 푸시

**1인 개발자가 쓸 수 있는 범위**로 제한하세요. 과한 인프라 제안 금지.

## 3. 수익 모델
초안은 "구독형 프리미엄, 월 4,900원 / 연 29,000원"입니다.
- 한국 앱 시장에서 이 가격이 적절한가 — 비슷한 학습 앱과 비교해 판단
- 무료 구간을 어디까지 열 것인가. **너무 좁으면 안 사고, 너무 넓으면 안 산다**
  이 경계를 어디에 두고, 왜 거기인가
- 구독 외 대안(평생 구매, 챕터별 구매)을 검토하고 채택/기각
- 첫 100명 유료 사용자를 어디서 데려올 것인가 — 채널 3개를 구체적으로

## 4. 로드맵
Phase 1/2/3을 **주 단위**로. 각 Phase마다:
- 산출물 / 소요 주수 / **이 단계를 통과했다고 판단하는 숫자 기준**
- 통과 못 하면 **무엇을 접는가** (이게 로드맵에서 제일 중요합니다)

## 5. 비용
1인 개발 기준 12개월 현금 지출. 원화 표로.
(개발자 계정, 서버, 도메인, 폰트/에셋, 코치 감수비, 초기 마케팅)
인건비는 제외하고, 대신 **총 소요 시간(주 단위)**을 따로 추정.

## 6. 리스크 5개
발생 확률 × 영향도로 순위를 매기고, 각각 **선행 지표**(무엇이 보이면 위험 신호인가)를 쓰세요.

## 7. 스토어 심사 체크리스트
iOS/안드로이드 각각, 이 앱이 반려될 수 있는 항목과 사전 대비.

## 금지
- "상황에 따라 다르다"로 결론을 회피하지 말 것. **하나를 고르세요**
- 근거 없는 시장 규모 숫자를 지어내지 말 것. 모르면 "확인 필요"로 표시
- 1인 개발자가 감당 못 할 인프라 (쿠버네티스, 마이크로서비스 등) 제안 금지

## 반박을 유도하는 이유

플랫폼 결정은 되돌리기 비싼 결정입니다.
AI에게 "정해줘"라고 하면 **당신이 이미 쓴 말을 되돌려줍니다.**
초안을 주고 반박하게 하면, 초안에 없던 리스크가 나옵니다.
그게 이 단계에서 얻어야 할 유일한 것입니다.
