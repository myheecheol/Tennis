당신은 스포츠 전술 다이어그램을 전문으로 하는 인터랙션 디자이너입니다.
위 카드 데이터를 화면에 그리는 **코트 렌더러 명세서**를 작성하세요.
개발자가 이 문서만 보고 구현할 수 있어야 합니다.

## 반드시 다뤄야 할 것

### 1. 캔버스와 좌표 변환
- 세로 화면(9:16) 기준, 코트를 **세로로 세워서** 그린다 (내가 아래, 상대가 위)
- 정규 좌표 → 화면 픽셀 변환식. 안전 여백(로브존과 끌려나간 마커가 잘리지 않게)
- 화면이 작을 때(360px 폭) 무엇을 먼저 버리는가

### 2. 시점 두 개 — 결정됨, 설계만 하세요
- **중계 시점**: 우리 뒤 높은 곳에서 망원으로. 코트 전체가 항상 보인다 (기본)
- **내 시점**: 내 등 뒤에서 네트 쪽을 본다. 네트 근처 장면에서만 기본값
- 공은 **실제 3D 포물선**으로 — 바닥 그림자, 바운드 링, `깊게/중간/짧게` 태그로 "길게 오는지 짧게 오는지"를 보여준다
- 각 시점에서 **존이 손가락으로 누를 만큼 보이는지**를 어떻게 보장할지 쓰세요

### 3. 마커 시스템
- `court-coordinates.md`의 색/모양 규칙을 지키되, **크기·테두리·그림자·라벨 위치**를 확정
- **"나" 마커는 어떻게 한눈에 튀게 만드는가** — 색 외에 2가지 장치를 더 쓴다
  (예: 은은한 발광 링, 미세한 맥동, 크기 차이 — 어떤 것을 왜 골랐는지)
- 색맹(적록) 사용자가 상대와 파트너를 구분할 수 있는가 — 검증 방법 포함

### 4. 화면 상태 5가지 — 각각 무엇이 보이고 무엇이 숨는가

| 상태 | 설명 |
|---|---|
| `setup` | 문제 제시. 마커 + 지나온 공 경로. 정답은 숨김 |
| `thinking` | 탭 가능한 존이 은은하게 드러남. 손가락이 존 위를 지날 때 반응 |
| `answered-correct` | 정답 존 강조 + 이동/타격 경로 애니메이션 |
| `answered-wrong` | 내가 고른 존 + 정답 존을 **동시에** 보여준다. 무엇이 다른지 |
| `replay` | 다음 수까지 이어서 재생 (`next.id`) |

각 상태의 화면을 **텍스트 와이어프레임**으로 그리세요.

### 5. 애니메이션 타임라인
정답 직후 재생되는 시퀀스를 **밀리초 단위 표**로. 총 길이는 2.5초를 넘지 않는다.

| 시각(ms) | 대상 | 동작 | 이징 |
|---|---|---|---|

- 공 경로는 **포물선**인가 직선인가 — 로브와 발리를 구분하는가
- `prefers-reduced-motion`일 때 무엇을 끄고 무엇을 남기는가

### 6. 탭 판정
- 존 히트박스는 시각적 존보다 넓은가 좁은가 (손가락 크기 44pt 고려)
- 존 경계 근처를 찍었을 때의 처리
- 오답을 찍었을 때 **되돌리기**를 허용하는가 (교육적으로 어느 쪽이 나은지 판단하고 이유)

### 7. 접근성
- 색·모양·글자 3중 인코딩 확인표
- 코트 그림을 못 보는 사용자를 위한 **텍스트 대체 서술 규칙** (자동 생성 문장 템플릿)
- 명암비: 모든 마커가 코트 배경 대비 4.5:1 이상인지 검증한 표

### 8. 디자인 토큰
색·간격·선 굵기·폰트 크기를 **이름 붙인 토큰 표**로. 다크/라이트 두 벌.

## 출력 형식
마크다운 명세서. 각 섹션에 텍스트 와이어프레임 포함.
마지막에 **"이 명세로 구현했을 때 가장 망가지기 쉬운 3곳"**과 그 대비책.

## 금지
- "직관적으로", "깔끔하게" 같은 측정 불가능한 표현
- 구체적 수치 없는 규칙 (모든 크기·시간·색은 값으로)
