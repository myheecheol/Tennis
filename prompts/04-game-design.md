# STEP 4 — 게임 디자인 프롬프트

**목적**: 상황 카드 더미를 **계속 하고 싶은 게임**으로 바꿉니다.
**입력**: STEP 0 + STEP 1 커리큘럼 + STEP 2 카드 샘플
**출력**: 코어 루프 / 모드 / 성장·보상 / 난이도 적응 / 리텐션 / 온보딩

---

```text
[STEP 0 공통 컨텍스트 블록을 여기 붙여넣기]
[STEP 1의 챕터 구조 + 카드 목록을 여기 붙여넣기]
[STEP 2에서 만든 카드 3~4장을 여기 붙여넣기]

---

당신은 학습형 모바일 게임 디자이너입니다.
듀오링고, 체스닷컴의 퍼즐 모드, 언어 학습 앱의 SRS(간격 반복)를 깊이 이해하고 있습니다.

위 상황 카드를 재료로, **주 4회 이상 돌아오는 학습 게임**을 설계하세요.

## 전제 — 이 제품의 특수성을 반영할 것
1. 정답이 **"하나"가 아니다.** 정답/차선/실수 3단계다. 점수 체계가 이걸 반영해야 한다
2. 사용자는 **주말에만 테니스를 친다.** 배운 걸 써먹는 주기가 일주일이다
3. 목표는 앱 안의 점수가 아니라 **코트 위의 행동 변화**다

## 설계할 것

### 1. 코어 루프
30초 안에 한 바퀴 도는 루프를 **단계별로**. 각 단계에서 사용자가 느끼는 감정을 한 단어로.
그리고 **"한 판 더" 버튼을 누르게 만드는 지점이 어디인지** 명시.

### 2. 채점 설계
- 정답 / 차선 / 실수를 어떻게 점수화하는가
- **차선을 골랐을 때가 가장 중요한 순간**입니다. 어떻게 "틀렸다"가 아니라
  "더 좋은 게 있었다"로 느끼게 만드는가 — 화면·문구·점수 세 가지로 답하세요
- 연속 정답(스트릭)에 보너스를 줄 것인가, 준다면 왜

### 3. 게임 모드 4가지
각각 이름 / 규칙 / 소요 시간 / 언제 하는가 / 해금 조건.
반드시 아래 성격이 하나씩 들어가야 한다:
- (a) **학습**: 새 개념을 배운다
- (b) **복습**: 틀린 것만 다시 (간격 반복 알고리즘 명시 — 며칠 뒤 다시 나오는가)
- (c) **압박**: 제한 시간. 코트에서는 생각할 시간이 없다는 걸 체감
- (d) **랠리**: 한 포인트를 **5수 연속** 판단. 앞선 선택이 다음 상황을 바꾼다
  → 이 모드의 분기 구조를 예시로 하나 그려 보이세요

### 4. 성장 시스템
- 무엇이 쌓이는가 (레벨? 등급? 실력 점수?)
- **테니스 세계관에서 자연스러운 이름**을 붙일 것 (일반적인 "레벨 5" 말고)
- 역할별 숙련도를 따로 보여줄 것인가 (서버/넷맨/리시버/리시버 파트너)
  → 이게 왜 좋은 아이디어인지 또는 왜 과한지 판단하세요

### 5. 난이도 적응
- 정답률에 따라 무엇을 조절하는가 (카드 난이도? 보기 개수? 제한 시간?)
- 너무 쉬우면 지루하고 너무 어려우면 이탈합니다. **목표 정답률 구간**을 숫자로 정하고 근거를 대세요

### 6. 리텐션 설계
- 푸시 알림 문구 5개. **"학습하세요" 같은 문구 금지.**
  실제 코트 상황을 던지는 형태로 (예: "상대가 로브를 올렸다. 누가 쫓아갈까?")
- 주간 리듬: 주말에 테니스를 치는 사용자에게 **화/금**은 각각 어떤 의미인가
- 스트릭을 도입할 것인가 — 도입 시 부작용(끊기면 이탈)과 그 완충 장치

### 7. 온보딩 첫 60초
설치 직후 첫 화면부터 **첫 정답을 맞힐 때까지**를 초 단위로 설계.
- 튜토리얼 텍스트는 **총 30자 이내**로 제한한다. 첫 문제 자체가 튜토리얼이어야 한다
- 첫 문제로 쓸 카드를 STEP 2 카드 중에서 고르고, 왜 그 카드인지 설명

### 8. 코트로 나가는 다리
앱 밖에서 실제로 쓰게 만드는 장치 1~2개를 제안하세요.
(예: 이번 주 미션 카드, 경기 후 30초 자가 점검)
아이디어의 나열이 아니라 **하나를 골라 구체적으로** 설계하세요.

## 출력 형식
각 항목을 표 또는 짧은 목록으로. 산문 설명은 항목당 3문장 이내.

## 마지막에 반드시
**"이 설계에서 가장 위험한 가정 3가지"**를 쓰고, 각각 무엇을 측정하면 검증되는지 적으세요.

## 금지
- "재미있게", "몰입감 있게" 같은 형용사로 때우는 설명
- 랜덤 뽑기, 에너지/하트 제한 같은 학습을 방해하는 과금 유도 장치
- 실시간 대전 (Non-goal)
```

```text
당신의 설계를 세 사람이 읽었습니다. 각각의 반론에 답하세요.

1. 테니스 코치: "앱에서 100점 맞아도 코트에선 몸이 안 움직인다.
   이 설계의 어느 부분이 실제 행동을 바꾸나?"
2. 게임 디자이너: "이건 퀴즈지 게임이 아니다. 플레이어가 내리는
   '의미 있는 선택'이 어디 있나?"
3. 우리 사용자(구력 8개월 직장인): "재미는 있었는데, 3일 하고 안 열게 됐다.
   왜 그랬을 것 같나?"

각 반론에 대해 (a) 인정할 부분 (b) 설계 변경안을 제시하세요.
변경안은 기존 설계의 어느 항목을 어떻게 바꾸는지 구체적으로.
```
