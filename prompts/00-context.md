# STEP 0 — 공통 컨텍스트 블록

> **모든 프롬프트(STEP 1~7) 맨 앞에 이 블록을 붙여 넣습니다.**
> 대화가 길어지면 AI가 프로젝트 설정을 잊습니다. 매 단계마다 다시 심어주는 게 핵심입니다.
> 아래 `<프로젝트>` 안쪽 전체를 복사하세요.

---

```text
<프로젝트>
## 우리가 만드는 것
테니스 복식의 "지금 어디로 움직이고, 공을 어디로 보내야 하는가"를
상황별 문제로 배우는 모바일 학습 게임.

## 핵심 사용자 (이 사람 한 명만 생각한다)
- 40대 직장인. 테니스 구력 8개월. 주말 동호회 복식만 침
- 스트로크는 어느 정도 되는데 **복식만 서면 얼어붙는다**
- 실제 고민: "내가 지금 여기 서 있는 게 맞나?", "이 공 어디로 쳐야 하지?",
  "파트너가 뒤로 가면 나도 가야 하나?"
- 유튜브를 봐도 남의 경기라 **내 시점이 아니라서** 안 와닿는다
- 하루 5분, 지하철에서 폰으로 공부한다

## 제품 한 줄
"코트 그림을 보고, 내가 어디로 갈지 / 공을 어디로 칠지 손가락으로 찍는다.
 찍으면 정답과 이유를 알려준다."

## 절대 규칙 (위반하면 다시 쓴다)
1. **1인칭.** 모든 화면은 "내가 우리 베이스라인에서 네트를 바라보는 시점". 카메라를 뒤집지 않는다
2. **내 마커는 항상 다른 색.** 한눈에 "나"를 찾을 수 있어야 한다
3. **전문 용어를 쓰기 전에 반드시 풀어 쓴다.** "포치" → "넷맨이 가운데로 나가 가로채는 것"
4. **정답은 항상 "왜"와 함께.** 이유 없는 정답은 암기이고, 코트에서 안 나온다
5. **오답도 실제로 사람들이 하는 선택이어야 한다.** 허수아비 보기 금지
6. **한 카드 = 한 가지 판단.** 두 개를 동시에 묻지 않는다
7. **분량보다 정확도.** 틀린 전술 100장보다 맞는 전술 30장

## 톤
- 코치가 코트 옆에서 짧게 말해 주는 **존댓말, 해요체**("~해요", "~할까요?"). 반말·해라체("~한다", "~할까?") 금지
- 강의체("~합니다")도 쓰지 않는다. 명사로 끝나는 짧은 문장("빠른 퍼스트 서브.")과 보기 라벨("가운데로 좁히기")은 괜찮다
- 감탄사·이모지 남발 금지. 핵심 문장은 굵게 하나만

## 하지 않을 것 (Non-goals)
- 스트로크 폼 교정, 서브 기술, 체력 훈련 → 다루지 않는다
- 단식 전술 → 다루지 않는다
- 실사 영상 → 코트 그림만 (v2부터 3D 원근 그림)
- 실시간 멀티플레이 → 1인 학습만
</프로젝트>
```
