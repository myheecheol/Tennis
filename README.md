## 이 키트가 보통 프롬프트와 다른 점

일반적인 "기획서 써줘" 프롬프트가 실패하는 이유는 세 가지입니다.
이 키트는 그 셋을 각각 막습니다.

**1. AI는 테니스 복식을 어설프게 압니다.**
그럴듯한데 틀린 전술이 나옵니다. "넷맨은 사이드라인을 지킨다" 같은 것들이요.
→ `doubles-domain-pack.md`가 **원칙과 금지 오답**을 미리 심습니다.

**2. "왼쪽 앞쪽"은 코드가 될 수 없습니다.**
게임을 만들려면 위치가 좌표여야 합니다.
→ `court-coordinates.md`가 **정규 좌표 + 존 코드 + JSON 스키마**를 고정합니다.

**3. 형식을 설명하면 AI는 형식만 흉내 냅니다.**
"좋은 오답을 만들어라"라고 해도 허수아비 보기가 나옵니다.
→ `card-exemplars.md`가 **완성본 2장**을 통째로 보여줍니다. 밀도가 전염됩니다.

여기에 더해 **분할 실행**(카드는 8장씩), **자기 검증 체크리스트**,
**반박 유도**(플랫폼 결정), **4인 페르소나 검수**가 들어 있습니다.

## 쓰는 법

1. `prompts/00-context.md`의 `<프로젝트>` 블록을 복사해 둡니다
2. STEP 1부터 순서대로 — 매번 **00 블록 + 해당 STEP 표의 reference 파일**을 함께 붙입니다
3. STEP 2(카드)는 **8장씩** 끊어서 반복합니다.
   잘 나온 카드 2장을 예시에 계속 추가하면 뒤로 갈수록 품질이 올라갑니다
4. STEP 6에서 조립하고, **STEP 7 검수를 반드시 거칩니다**

### AI가 헤맬 때

| 증상 | 처방 |
|---|---|
| 카드가 다 비슷하다 | 배치를 8장 이하로 줄인다 |
| 전술이 틀렸다 | 도메인 팩을 **요약 말고 전문**으로 붙였는지 확인 |
| 오답이 허수아비다 | `차선`/`실수` 구분 규칙을 다시 강조 |
| 해설이 뜬구름 | "네트 높이·거리·몸의 방향으로 설명하라"를 추가 |
| 대화가 길어져 설정을 잊음 | 00 블록을 다시 붙인다 |

---

## AI 검수로는 안 되는 것

- **전술 오류** → 실제 코치 2인 감수. 이게 틀리면 제품 신뢰가 통째로 날아갑니다
- **재미** → 앱을 만들기 전에 **카드를 종이에 인쇄해서** 동호인 5명에게 풀려보세요.
  종이로 재미없으면 앱으로 만들어도 재미없습니다

## 플랫폼 질문에 대한 짧은 답

> 웹앱보다 iOS/안드로이드 앱이 맞을까?

**최종 형태는 앱이 맞고, 시작은 웹이 맞습니다.**
푸시 알림과 인앱결제 때문에 학습 앱은 결국 모바일로 가야 합니다.
하지만 이 프로젝트의 진짜 리스크는 기술이 아니라 **콘텐츠가 재미있는가**이고,
그건 링크 하나로 30명에게 물어보는 게 가장 빠릅니다.

자세한 근거·대안 비교·가격·로드맵은 `reference/platform-recommendation.md`에 있습니다.
